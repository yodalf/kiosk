# CLAUDE.md

Guidance for Claude Code when working in this repo.

## Workflow Preferences

**Git commit and push policy**
- NEVER commit or push without an explicit instruction from the user.
- After making changes, show what was done and wait for the user to say
  "commit and push" (or similar) before running any git write commands.
- This applies to every session and every change.

## What this project is

Single-file-ish shell project: a fullscreen video kiosk for Raspberry Pi that
drives `mpv` over an IPC socket to rotate through a playlist of YouTube URLs
with seamless transitions. Full design and runtime internals live in
**[ARCHITECTURE.md](ARCHITECTURE.md)** — read that first for anything beyond
surface-level changes.

## Files in the repo

| File | Role |
|------|------|
| `kiosk.sh` | Runtime script. Spawns mpv, manages rotation, runs OCR highlight monitor. |
| `kiosk-setup.sh` | Idempotent installer. Copies scripts to `$HOME`, installs systemd units, configures autologin. |
| `kiosk-with-x.sh` | Template; real copy is generated by `kiosk-setup.sh` with the username hardcoded. |
| `kiosk.service` / `kiosk-monitor.service` | Systemd unit templates. `USERNAME` is substituted at install. |
| `kiosk-monitor.sh` / `restart-kiosk.sh` | Watchdog + restart helpers. |
| `wifi-watchdog.sh` / `.service` / `.timer` | Wi-Fi link watchdog (every minute, root). Bounces the link after 3 failed checks, reboots after 6. Needs `tcpdump` + `jq`. |
| `99-vc4.conf` | Xorg config for the Raspberry Pi 5 dual-DRM GPU. |
| `*.url` | Playlists. `kiosk.url` is the active one; setup symlinks or copies. |
| `README.md` | User-facing quick start. |
| `ARCHITECTURE.md` | High-level overview down to `kiosk.sh` internals. Canonical source for how it works. |

## Deploy target

Live Pi at `realo@192.168.2.10` (or `raspi5.local`), password `toto`. The Pi
runs a copy of `kiosk.sh` in `~/` — the repo is on the dev machine.

Deploy flow:
```bash
sshpass -p 'toto' scp -o StrictHostKeyChecking=no kiosk.sh realo@192.168.2.10:/home/realo/kiosk.sh
sshpass -p 'toto' ssh  -o StrictHostKeyChecking=no realo@192.168.2.10 'sudo systemctl restart kiosk.service'
```

For URL files (`*.url`), the running kiosk auto-detects edits to `~/kiosk.url`
within a few seconds — no restart needed.

The same Pi also hosts two things that are not part of this repo but that
`wifi-watchdog.sh` and any network change must respect:

- **Pi-hole v6** (bare metal, `pihole-FTL` owns ports 53/80/443). Its only
  upstream is `127.0.0.1#5335`, a local `unbound` that forwards to Quad9 over
  DNS-over-TLS (`/etc/unbound/unbound.conf.d/quad9-dot.conf`). Listening mode
  is `ALL` so tailnet clients are answered.
- **Tailscale** joined to the Headscale server at `hs.realo.ca` as node
  `kiosk`, tailnet IP `100.64.0.5`, started with `--accept-dns=false`. The
  whole tailnet uses this Pi-hole as its resolver, so an outage of the Pi
  takes tailnet DNS with it. The Pi is also reachable at
  `realo@100.64.0.5` from any tailnet device.

## When modifying `kiosk.sh`

- Bash 5+ is available on the target (uses `mapfile`, `shuf`, bash regex).
  macOS bash 3.2 won't run it — test on the Pi via ssh.
- `stat` uses both `-f%z` (BSD) and `-c%s` (GNU) for portability.
- Log to `/tmp/kiosk.log` via `log_message` (prepends timestamp + rotates at 1 MB).
- The single `rotate_to_next "<reason>"` helper is the only path that should
  switch URLs. Don't reintroduce duplicated load/log/timer-reset sequences.
- Shuffle state is an in-memory bash array + index — do not reintroduce the
  old `/tmp/kiosk_shuffle*` files.
- Live test: replace `~/kiosk.sh` on the Pi and `systemctl restart kiosk.service`,
  then tail `/tmp/kiosk.log` for ~30 s to catch startup, first rotation, and
  highlight monitor output.

## Boot behaviour

On a fresh boot the kiosk normally needs **2–3 start attempts** before X gets
exclusive VT1 control. This is expected: `Restart=always` + `RestartSec=10`
handles it automatically. The kiosk is typically playing within ~60 s of boot.
Do **not** "fix" this by reverting to `Restart=on-failure` — `startx` always
exits 0 (even on failure), so `on-failure` never fires.

## Key `kiosk.service` design decisions

| Setting | Value | Reason |
|---------|-------|--------|
| `Restart` | `always` | `startx` exits 0 even when `kiosk.sh` fails; `on-failure` would never retry |
| `StandardOutput` | `journal` | Original `tty` kept /dev/tty1 open in the service process while X was trying to take exclusive VT control — race condition on first boot |
| `StandardError` | `journal` | Same as above; errors now visible via `journalctl -u kiosk.service` |
| `Environment=XDG_RUNTIME_DIR` | `/run/user/%U` | mpv requires this; the system service environment doesn't set it |

## Debugging startup failures

- **`/tmp/kiosk-startx.log`** — stdout/stderr from `startx` and `kiosk.sh`
  (X init messages, mpv startup errors, echo lines from the script).
- **`/tmp/kiosk.log`** — timestamped runtime log from `kiosk.sh` (rotations,
  OCR results, stuck-playback events).
- **`journalctl -b -u kiosk.service`** — systemd-level events (start/stop/restart cycles, mpv stderr).
- **`~/.local/share/xorg/Xorg.0.log`** — full X server log.

## When modifying `kiosk-setup.sh`

- Must remain idempotent — re-running on an already-set-up Pi must be safe.
- Must not run as root; it uses `sudo` only for system-level bits.
- Required packages: `unclutter socat mpv yt-dlp xorg xinit tesseract-ocr ffmpeg tcpdump jq`
  (`ffmpeg` is used by `kiosk.sh` to preprocess screenshots before OCR;
  `tcpdump` and `jq` by `wifi-watchdog.sh`).
- If changing installed packages, update `apt-get install` and mention in
  ARCHITECTURE.md's platform notes.
